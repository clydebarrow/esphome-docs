The `filesystem` component keeps files and directories on a [storage](/components/storage/) device. Each
filesystem type is a platform of the `filesystem` component:

- [FAT](/components/filesystem/fatfs/): the FAT12, FAT16 and FAT32 filesystems used on most SD cards.

Other components use a filesystem to read and write files, for example the
[filesystem image](/components/image/filesystem/) platform, which shows images stored on an SD card. A
[file](/components/file/) entry names a path on a filesystem, for use in automations.

```yaml
storage:
  - platform: sd_spi
    id: sd_card
    cs_pin: GPIOXX

filesystem:
  - platform: fatfs
    id: sd_files
    storage_id: sd_card
```

The filesystem is mounted at boot when the storage device has media, and otherwise the first time it is used
after media is inserted. When the media is changed, the filesystem mounts the new media the next time it is
used.

## Configuration variables

These options are common to all filesystem platforms:

- **storage_id** (*Optional*, [ID](/guides/configuration-types#id)): The storage device that holds the
  filesystem. Only needed with more than one storage device.
- **max_open_files** (*Optional*, int): The number of files that lambdas can have open at the same time, from 0
  to 32. Defaults to `2`. Components that keep files open, such as the filesystem image, add the files they
  need to this, so it only needs to cover your own lambdas.
- **max_open_dirs** (*Optional*, int): The number of directories that lambdas can have open at the same time,
  from 0 to 8. Defaults to `1`.
- **format_if_mount_failed** (*Optional*, boolean): Create a new, empty filesystem when the media holds no
  filesystem of this type. Defaults to `false`.

  > [!WARNING]
  > Formatting erases everything on the media. With this option set, a card that holds a different
  > filesystem, or one that is damaged, is erased when it is inserted.

- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code generation.

Each open file and directory takes some RAM, set aside at boot; keep the limits as low as your use allows.

## Use in lambdas

Paths are absolute, start with `/`, and use `/` between names. A method that can fail returns a
`filesystem::FsError`, which is `filesystem::FsError::FS_ERROR_NONE` on success.

- `open(path, flags)`: open a file. Returns a `filesystem::File`, which is closed when it goes out of scope.
  Check it with `if (file)`; when it is not open, `last_error()` says why. `flags` is a combination of:
  - `filesystem::OPEN_READ`, `filesystem::OPEN_WRITE`: open for reading, writing or both. At least one is needed.
  - `filesystem::OPEN_CREATE`: create the file if it does not exist.
  - `filesystem::OPEN_TRUNCATE`: empty the file if it exists.
  - `filesystem::OPEN_APPEND`: start at the end of the file.
  - `filesystem::OPEN_EXCLUSIVE`: with `OPEN_CREATE`, fail if the file already exists.
- `open_dir(path)`: open a directory. Returns a `filesystem::Dir`, read with `read_next(info, name, name_size)`.
- `stat(path, info)`: fill a `filesystem::FileInfo` with the `size`, modification time `mtime` (seconds since
  1970) and `is_dir` of a file or directory.
- `mkdir(path)`, `remove(path)`, `rename(from, to)`: create a directory, remove a file or empty directory, or
  rename a file or directory.
- `space(total, free)`: the size and free space of the filesystem in bytes.
- `format()`: erase the media and create a new, empty filesystem.
- `is_mounted()`, `mount()`, `unmount()`: check, or change, whether the filesystem is mounted. Calls mount it
  when needed, so `mount()` is rarely needed; `unmount()` closes all open files, for example before the media
  is removed.

A `filesystem::File` has `read(buf, len)`, `write(buf, len)`, `seek(offset)`, `tell()`, `size()`, `sync()`,
`truncate()` and `close()`. `read`, `write` and `seek` return a byte count or position, or a negative
`FsError`. Call `sync()` to make sure written data is stored on the media without closing the file.

```yaml
interval:
  - interval: 60s
    then:
      - lambda: |-
          auto file = id(sd_files).open("/log.txt", filesystem::OPEN_WRITE | filesystem::OPEN_CREATE |
                                                     filesystem::OPEN_APPEND);
          if (!file) {
            ESP_LOGW("log", "Open failed: %s",
                     LOG_STR_ARG(filesystem::fs_error_to_string(id(sd_files).last_error())));
            return;
          }
          char line[32];
          int len = snprintf(line, sizeof(line), "%.1f\n", id(temperature).state);
          file.write(line, len);
```

The filesystem is not safe to use from more than one task at a time; use it from the main loop, as lambdas
and automations do.
